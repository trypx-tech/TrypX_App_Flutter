TASK F-05 - Onboarding flow controller (pure Dart, no UI / no Firebase)

Build the state machine that drives the supply-side onboarding funnel (SCREENS.md S-01..S-07, with the S-08/S-09 social-vs-manual fork). This is PURE Dart: no widgets, no Firebase, no I/O. It consumes the submission models from F-03 and the enums from F-01. UI screens are a later task.

## Scope / invariants
- Persona fork at step 1 (invariant 11): role select routes Traveller out of the funnel; Creator/Expert continues.
- Language step is MANDATORY (invariant 14): the flow cannot complete without >=1 language.
- At least one DEEP place is required (SCREENS.md S-04): `PlaceDepth.livedThere` or `PlaceDepth.frequent` counts as deep; `visited` does not.
- No-social path is allowed (invariant 19): social is NEVER required. If the user skips social, the flow routes to the manual places-claim step. Instagram is never forced.
- Submit writes `status=submitted` ONLY — this controller never approves and never calls ApprovalGate (invariant 12). It only decides whether a submission is structurally complete and ready to submit.
- Do NOT touch pubspec, Firebase config, or secrets (invariant 21).

2.2 Define a result sealed-style type for validation. Prefer a simple immutable class hierarchy (no external deps):

```dart
/// Outcome of validating the current onboarding step.
sealed class StepValidation {
  const StepValidation();
}

class StepValid extends StepValidation {
  const StepValid();
}

class StepInvalid extends StepValidation {
  const StepInvalid(this.reason);
  final String reason;

  @override
  bool operator ==(Object other) {
    return other is StepInvalid && other.reason == reason;
  }

  @override
  int get hashCode => reason.hashCode;
}
```

2.3 `class OnboardingFlow` holds the in-progress draft state (NOT persisted). Fields (all nullable/empty-initialised; mutate via explicit setters or a copy — your choice, but keep it immutable-friendly and tested):
- `Persona? persona`
- `String displayName` (default `''`)
- `SocialLink? social` (null == chose the no-social / manual path, invariant 19)
- `bool skippedSocial` (default `false`)
- `List<PlaceClaim> places` (default `const []`)
- `List<LanguageClaim> languages` (default `const []`)
- `DateTime? interviewStartsAt`

2.4 `OnboardingStep get currentStep` — tracked internally, starts at `OnboardingStep.roleSelect`.

2.5 `StepValidation validateStep(OnboardingStep step)` — PURE given current state. Rules per step (use these exact reason strings):
- `roleSelect`: valid only if `persona != null`; else `StepInvalid('Select a persona')`.
- `landing`: always `StepValid()`.
- `connectStory`: valid only if `displayName.trim().isNotEmpty`; else `StepInvalid('Display name required')`.
- `connectSocial`: valid if EITHER `skippedSocial == true` OR `social != null` (social never required, invariant 19). Else `StepInvalid('Connect a social account or choose manual')`.
- `manualPlaces`: always `StepValid()` (it is an entry surface; place validity is enforced at `places`).
- `places`: valid only if `places` contains at least one DEEP claim (`PlaceDepth.livedThere` or `PlaceDepth.frequent`); else `StepInvalid('Add at least one place you know deeply')`.
- `languages`: valid only if `languages.isNotEmpty` (invariant 14); else `StepInvalid('Add at least one language')`.
- `interviewSlot`: valid only if `interviewStartsAt != null`; else `StepInvalid('Pick an interview slot')`.
- `whatNext`: valid only if ALL of `roleSelect, connectStory, connectSocial, places, languages, interviewSlot` are valid; else `StepInvalid('Complete all required steps')`.

2.6 `OnboardingStep? next()` — advances from `currentStep` to the next step and returns it, mutating `currentStep`. Navigation rules:
- Returns `null` and does NOT advance if `validateStep(currentStep)` is `StepInvalid` (you cannot leave an invalid step).
- Fork at `roleSelect`: if `persona` routes a Traveller out of the funnel, return `null` and set a flag/throw per 2.8 — Travellers do not continue. (If `Persona` enum has no traveller value, treat BOTH personas as continuing; document in a comment. If unclear, emit NEEDS-DECISION.)
- Social fork: from `connectSocial`, if `skippedSocial == true`, advance to `manualPlaces`; otherwise skip `manualPlaces` and advance to `places`.
- From `manualPlaces`, advance to `places`.
- Normal case: advance to the next enum value in order.
- At `whatNext` (the last step), `next()` returns `null` (nothing after submit).

2.7 `bool get canSubmit` — true iff `validateStep(OnboardingStep.whatNext)` is `StepValid`.

2.8 `ApplicationSubmission buildSubmission()` — only callable when `canSubmit`. If `!canSubmit`, throw `StateError('Onboarding incomplete')`. Otherwise construct an `ApplicationSubmission` from the current draft. `social` is passed through as-is (null for the manual path). Per invariant 12 this method produces the submission object ONLY; it sets no status and performs no approval. If `ApplicationSubmission`'s constructor shape is unknown, emit NEEDS-DECISION rather than inventing fields.
